# Q2 Identify **ALL** the issues and explain how to fix them:

## Original Code
```javascript
async function updateUserProfile(userId, newData) {
  const user = await db.users.findById(userId);
  user.profileViews += 1;
  const updated = { ...user, ...newData };
  await db.users.update(userId, updated);
  return updated;
}
```
---

## Issues

### 1. Race Condition (Lost Update)
**Location:** Between `findById` and `update`.
**The Problem:** If two requests call `updateUserProfile` for the same user at the same time, both will read the same `profileViews` value (e.g., `5`), independently increment it to `6`, and both write `6` back — losing one increment. This is a classic **read-modify-write race condition**.
**The Fix:** Increment `profileViews` atomically on the database level using an increment operation, rather than reading, modifying, and writing back in application code.
```javascript
// ❌ Problem
const user = await db.users.findById(userId);
user.profileViews += 1;
await db.users.update(userId, updated);

// ✅ Solution
await db.users.increment(userId, { profileViews: 1 });
```

---

### 2. `newData` Can Overwrite `profileViews` (and other protected fields)
**Location:** The spread `{ ...user, ...newData }`.
**The Problem:** Because `newData` is spread after `user`, a caller can pass `{ profileViews: 0 }` (or any internal field like `id`, `createdAt`, `role`) inside `newData` and silently overwrite it. There is no sanitisation of what is allowed to be updated.
**The Fix:** Explicitly whitelist the fields that `newData` is allowed to change, or explicitly exclude protected fields before merging.
```javascript
// ❌ Problem
const updated = { ...user, ...newData };

// ✅ Solution — destructure out protected fields and discard them
const { id, profileViews, createdAt, role, ...safeData } = newData;
const updated = { ...user, ...safeData };
```

---

### 3. No Error Handling / Null Check
**Location:** `const user = await db.users.findById(userId)`.
**The Problem:** If `userId` does not exist, `findById` likely returns `null` or `undefined`. The immediately following `user.profileViews += 1` will throw a `TypeError: Cannot read properties of null`, crashing the function without a meaningful error message to the caller.
**The Fix:** Check that the user was found before proceeding, and wrap the operation in a `try/catch`.
```javascript
// ❌ Problem
const user = await db.users.findById(userId);
user.profileViews += 1; // throws if user is null

// ✅ Solution
const user = await db.users.findById(userId);
if (!user) {
  throw new Error(`User with id ${userId} not found`);
}
```

---

### 4. No Input Validation
**Location:** Function parameters `userId` and `newData`.
**The Problem:** The function accepts `userId` and `newData` without any validation. A missing, malformed, or malicious `userId` (e.g., SQL/NoSQL injection payload) can cause unexpected database behaviour or security vulnerabilities. Similarly, `newData` being `null` or a non-object will cause the spread to throw.
**The Fix:** Validate inputs at the boundary before any database interaction.
```javascript
// ❌ Problem
async function updateUserProfile(userId, newData) {
  // No checks — userId could be anything, newData could be null

// ✅ Solution
async function updateUserProfile(userId, newData) {
  if (!userId) throw new Error('userId is required');
  if (!newData || typeof newData !== 'object' || Array.isArray(newData)) {
    throw new Error('newData must be a non-null object');
  }
  // ...
}
```

---

### 5. The Returned `updated` Object May Be Stale
**Location:** `return updated`.
**The Problem:** The function constructs `updated` in memory and returns it directly without re-reading from the database. If the `db.users.update` call transforms the data (e.g., server-side timestamps, triggers, default values), the returned object will not reflect the true persisted state.
**The Fix:** Return the result of the update call, or re-fetch the record after updating.
```javascript
// ❌ Problem
await db.users.update(userId, updated);
return updated; // may not match what was actually saved

// ✅ Solution
await db.users.update(userId, updated);
return await db.users.findById(userId); // always reflects persisted state
```

---

## ✅ Complete Solution

```javascript
async function updateUserProfile(userId, newData) {
  // 1. Input validation
  if (!userId) throw new Error('userId is required');
  if (!newData || typeof newData !== 'object' || Array.isArray(newData)) {
    throw new Error('newData must be a non-null object');
  }

  try {
    // 2. Null check
    const user = await db.users.findById(userId);
    if (!user) throw new Error(`User with id ${userId} not found`);

    // 3. Strip protected fields from newData before merging
    const { id, profileViews, createdAt, role, ...safeData } = newData;
    const updated = { ...user, ...safeData };

    // 4. Apply safe update
    await db.users.update(userId, updated);

    // 5. Atomically increment profileViews to avoid race condition
    await db.users.increment(userId, { profileViews: 1 });

    // 6. Return the true persisted state
    return await db.users.findById(userId);
  } catch (err) {
    console.error(`Failed to update user profile for ${userId}:`, err);
    throw err;
  }
}
```
